# 🛠 DevTool CLI (`dev`)

> **Маленький, быстрый и расширяемый CLI-лаунчер скриптов для разработчиков и DevOps.**  
> Забудьте о гигантском и нечитаемом `.bashrc` с десятками `alias`. Все сценарии хранятся в виде чистых модульных `.sh` файлов с декларативными заголовками, версионируются через Git и запускаются одной командой.

## ✨ Возможности

- **Единая точка входа**: команда `dev` доступна из любого каталога.
- **Интерактивное меню с `fzf`**: нечеткий поиск команд с живым превью описания, параметров и кода скрипта прямо в терминале.
- **Резервное меню**: если `fzf` не установлен, работает чистое нумерованное Bash-меню без внешних зависимостей.
- **Гибкий синтаксис вызова**:
  - `dev git sync main` (категория + команда)
  - `dev git-sync main` (через дефис, как короткий alias)
  - `dev git:sync main` (через двоеточие)
  - `dev health` (быстрый вызов по уникальному имени)
- **Умная трехуровневая база**: проектные скрипты (`.dev/`), пользовательские скрипты (`~/.config/devtool/scripts/`) и базовая библиотека из репозитория.
- **Встроенная безопасность**: операции, помеченные как `# @dangerous true`, запрашивают подтверждение пользователя перед выполнением (можно пропустить флагом `--force` или `-y`).
- **Самообновление через Git**: команда `dev update` автоматически подтягивает изменения из вашего репозитория.

## 🏗 Архитектура хранилища

Каждый скрипт — это независимый bash-файл с декларативным блоком метаданных в начале:

```bash
#!/usr/bin/env bash
# @name Git Sync
# @description Синхронизировать текущую или указанную ветку с origin
# @usage dev git sync [branch]
# @dangerous false

set -e
# Логика вашего скрипта...
```

### Структура репозитория

```text
devtool-script/
├── bin/
│   └── dev                  # Главный исполняемый CLI-лаунчер
├── lib/
│   └── utils.sh             # Движок метаданных, цвета, подтверждения, поиск
├── scripts/                 # Базовое хранилище ("база из коробки")
│   ├── git/                 # Сценарии Git
│   │   ├── sync.sh
│   │   ├── clean.sh
│   │   ├── reset-main.sh
│   │   ├── squash.sh
│   │   └── log.sh
│   ├── docker/              # Сценарии Docker и Compose
│   │   ├── clean.sh
│   │   ├── rebuild.sh
│   │   ├── ps.sh
│   │   └── stop-all.sh
│   ├── laravel/             # Сценарии для Laravel / PHP (с поддержкой Sail)
│   │   ├── reset.sh
│   │   ├── cache-clear.sh
│   │   ├── migrate.sh
│   │   └── tinker.sh
│   ├── server/              # Серверные утилиты и DevOps
│   │   ├── deploy.sh
│   │   ├── permissions.sh
│   │   └── health.sh
│   └── dev/                 # Служебные утилиты devtool
│       ├── update.sh        # Обновление лаунчера через git pull
│       ├── doctor.sh        # Проверка окружения и утилит
│       └── create.sh        # Генератор новых скриптов
├── install.sh               # Скрипт быстрой установки
├── uninstall.sh             # Скрипт удаления
└── README.md
```

### Приоритет поиска скриптов (от высшего к низшему):
1. **Проектный уровень**: `./.dev/scripts/` или `./.dev/` в корне текущего рабочего каталога (позволяет переопределять или расширять команды под конкретный проект).
2. **Пользовательский уровень**: `~/.config/devtool/scripts/` или `~/.devtools/scripts/` (ваши персональные команды, не входящие в общий git-репозиторий).
3. **Базовый уровень**: `$DEV_ROOT_DIR/scripts/` (встроенные скрипты из этого репозитория).

## 🚀 Установка и быстрый старт

### 1. Клонирование репозитория

Склонируйте репозиторий в удобную папку (например, `~/dev/devtool-script` или `~/.devtools`):

```bash
git clone <URL_ВАШЕГО_РЕПОЗИТОРИЯ> ~/dev/devtool-script
cd ~/dev/devtool-script
```

### 2. Запуск установщика

```bash
./install.sh
```

> **Что делает `install.sh`:**
> - Выставляет права на исполнение (`chmod +x`) на скрипты и лаунчер.
> - Создает символическую ссылку `/usr/local/bin/dev` (или `~/.local/bin/dev`, если запуск без `sudo`).
> - Проверяет наличие `fzf` и Bash версии 4+.

Если вы хотите установить `dev` только для текущего пользователя без прав `sudo`:
```bash
./install.sh --user
```
*(Убедитесь, что `~/.local/bin` добавлен в ваш `$PATH`).*

### 3. Рекомендуется: установить `fzf` (для интерактивного поиска)

```bash
# Ubuntu / Debian
sudo apt install fzf

# macOS
brew install fzf

# Fedora / RedHat
sudo dnf install fzf
```

## 💻 Использование CLI

### 1. Интерактивный режим

Просто запустите команду:
```bash
dev
```
Откроется интерактивный поиск `fzf` со списком всех доступных команд, их описанием и превью кода в правой панели. Начните вводить текст (например, `dock` или `sync`) и нажмите `Enter` для запуска.

Если вы хотите открыть меню только для определенной категории:
```bash
dev git
dev docker
dev laravel
```

### 2. Прямой запуск команд

Команды можно вызывать напрямую с передачей любых параметров:

```bash
# Формат 1: категория + команда
dev git sync
dev git sync feature-login
dev docker rebuild web
dev laravel migrate --seed
dev server health

# Формат 2: через дефис (как алиасы)
dev git-sync
dev docker-clean
dev laravel-reset

# Формат 3: через двоеточие
dev git:sync
dev docker:clean
```

### 3. Защита опасных операций (`@dangerous`)

Скрипты, изменяющие состояние данных или удаляющие файлы (например: `git reset-main`, `git clean`, `docker clean`, `laravel reset`, `server deploy`), помечены флагом `# @dangerous true`.

При их запуске лаунчер выведет предупреждение:

```text
┌─────────────────────────────────────────────────────────────┐
│  ⚠️   ВНИМАНИЕ: ОПАСНАЯ ОПЕРАЦИЯ!                            │
└─────────────────────────────────────────────────────────────┘
  Команда:     git reset-main (Git Reset Main)
  Описание:    Жестко сбросить ветку main к состоянию origin с удалением изменений
  Скрипт:      .../scripts/git/reset-main.sh

Эта операция может изменить или удалить локальные данные / ресурсы.
Вы действительно хотите продолжить? [y/N]: 
```

Если вы запускаете команду в CI/CD или автоматическом скрипте, подтверждение можно пропустить флагом `--force` или `-y`:

```bash
dev --force git reset-main
# или
dev -y docker clean
```

## 📦 Базовые команды "из коробки"

Посмотреть актуальную таблицу всех команд в терминале:
```bash
dev list
```

| Команда | Опасность | Описание |
| :--- | :---: | :--- |
| **`dev git sync [branch]`** | Нет | Забирает `origin` с `prune` и делает `git pull --ff-only` |
| **`dev git clean [-x]`** | **ДА** | Очищает неотслеживаемые файлы (`git clean -fd`) |
| **`dev git reset-main`** | **ДА** | Жестко сбрасывает текущую `main` (или `master`) на `origin/main` |
| **`dev git squash [count]`** | **ДА** | Объединяет последние N коммитов в staging (`git reset --soft HEAD~N`) |
| **`dev git log [count]`** | Нет | Красивое цветное дерево последних коммитов |
| **`dev docker clean [--all]`** | **ДА** | Удаляет неиспользуемые контейнеры, сети и образы (`docker system prune`) |
| **`dev docker rebuild [svc]`** | Нет | Пересобирает и перезапускает сервисы без кэша (`compose build --no-cache`) |
| **`dev docker ps`** | Нет | Статус контейнеров, маппинг портов и статистика RAM/CPU |
| **`dev docker stop-all`** | **ДА** | Мягко останавливает все запущенные Docker-контейнеры |
| **`dev laravel reset`** | **ДА** | Полный сброс БД и кэшей (`migrate:fresh --seed`, `optimize:clear`) |
| **`dev laravel cache-clear`** | Нет | Очистка всех кэшей конфигурации, роутов и вьюшек |
| **`dev laravel migrate`** | Нет | Выполнение ожидающих миграций базы данных |
| **`dev laravel tinker`** | Нет | Интерактивная консоль Laravel Tinker |
| **`dev server deploy [branch]`** | **ДА** | Пошаговый сценарий деплоя (Git pull, Composer, NPM build, миграции) |
| **`dev server permissions`** | **ДА** | Установка безопасных прав (каталоги 755, файлы 644, storage 775) |
| **`dev server health`** | Нет | Мониторинг RAM, дисков, нагрузки CPU и слушающих портов |
| **`dev update`** | Нет | Обновление devtool-script из Git |
| **`dev doctor`** | Нет | Проверка установленных утилит (bash, git, docker, php, node, fzf) |
| **`dev dev create`** | Нет | Интерактивный генератор шаблона нового скрипта |

## ✍️ Добавление своих команд

Вам **не нужно** редактировать исходный код лаунчера `bin/dev`. Достаточно просто добавить `.sh` файл!

### Способ 1: Использовать встроенный генератор

```bash
dev dev create mytools backup
```

Генератор автоматически создаст файл `scripts/mytools/backup.sh` с правильными заголовками:

```bash
#!/usr/bin/env bash
# @name Mytools Backup
# @description Описание того, что делает этот сценарий
# @usage dev mytools backup [параметры]
# @dangerous false

set -e

echo "==> Выполнение Mytools Backup..."
# Ваш bash код здесь
```

### Способ 2: Вручную создать файл

Создайте файл в папке категории, например `scripts/docker/logs.sh`:

```bash
#!/usr/bin/env bash
# @name Docker Service Logs
# @description Просмотр логов сервиса Docker Compose в реальном времени
# @usage dev docker logs [service_name]
# @dangerous false

set -e
docker compose logs -f --tail=100 "${1:-}"
```

Сделайте файл исполняемым:
```bash
chmod +x scripts/docker/logs.sh
```

Команда **сразу же** появится в `dev list`, меню `fzf` и будет доступна для вызова:
```bash
dev docker logs app
```

### Способ 3: Скрипты конкретного проекта

Если в вашем рабочем репозитории есть скрипты, нужные только в этом проекте, положите их в `.dev/scripts/` внутри проекта:

```text
my-project/
├── .dev/
│   └── scripts/
│       └── test/
│           └── run-e2e.sh
├── app/
└── ...
```
Когда вы находитесь в папке `my-project`, команда `dev test run-e2e` будет автоматически доступна!

## 🔄 Обновление и диагностика

### Проверка системы (`doctor`)
```bash
dev doctor
```
Проверяет наличие `bash 4+`, `git`, `docker`, `php`, `fzf` и показывает пути к каталогам скриптов.

### Обновление лаунчера
Так как утилита работает через Git, для обновления достаточно одной команды:
```bash
dev update
```
Она выполнит `git pull --ff-only` в репозитории devtool и обновит права на все новые скрипты.

## 🗑 Удаление

Если вы хотите удалить символические ссылки `dev`:
```bash
./uninstall.sh
```
После этого можно удалить саму директорию с репозиторием.
