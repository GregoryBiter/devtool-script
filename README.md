# 🛠 DevTool CLI (`dev`)

> **Маленький, быстрый и расширяемый CLI-лаунчер скриптов для разработчиков и DevOps.**  
> Забудьте о гигантском и нечитаемом `.bashrc` с десятками `alias`. Все сценарии хранятся в виде чистых модульных `.sh` файлов с декларативными заголовками, версионируются через Git и запускаются одной командой.

---

## ⚡ Быстрая установка в одну команду

Скопируйте и выполните в терминале (Linux / macOS / WSL):

```bash
curl -fsSL https://raw.githubusercontent.com/GregoryBiter/devtool-script/main/install.sh | bash
```

После установки команда `dev` сразу готова к работе:

```bash
dev            # Открыть интерактивное меню (поиск и превью команд)
dev list       # Таблица всех доступных команд с описанием
dev update     # Автоматическое обновление из Git
```

> **Что делает скрипт установки:**
> 1. Клонирует репозиторий `https://github.com/GregoryBiter/devtool-script.git` в каталог `~/.devtools` (если уже установлен — выполняет `git pull`).
> 2. Выставляет права на исполнение (`chmod +x`) на лаунчер и скрипты.
> 3. Создает символическую ссылку `dev` в `~/.local/bin/dev` (не требует прав `sudo`, безопасно для curl).
> 4. Автоматически добавляет путь в `~/.bashrc` / `~/.zshrc` (если `~/.local/bin` не был в `$PATH`).
> 5. Проверяет окружение и рекомендует `fzf` для интерактивного меню.

## ✨ Возможности

- **Единая точка входа**: команда `dev` доступна из любого каталога.
- **Интерактивное меню с `fzf`**: нечеткий поиск команд с живым превью описания, параметров и кода скрипта прямо в терминале.
- **Резервное меню**: если `fzf` не установлен, работает чистое нумерованное Bash-меню без внешних зависимостей.
- **Гибкий синтаксис вызова**:
  - `dev git sync main` (категория + команда)
  - `dev git-sync main` (через дефис, как короткий alias)
  - `dev git:sync main` (через двоеточие)
  - `dev health` (быстрый вызов по уникальному имени)
- **Умная трехуровневая база**: проектные скрипты (`.dev/`), пользовательские скрипты (`~/.config/devtool/scripts/`) и базовая библиотека из репозитория.
- **Встроенная безопасность**: операции, помеченные как `# @dangerous true`, запрашивают подтверждение пользователя перед выполнением (можно пропустить флагом `--force` или `-y`).
- **Самообновление через Git**: команда `dev update` автоматически подтягивает изменения из вашего репозитория.

## 💻 Использование CLI

### 1. Интерактивный режим

Просто запустите команду:
```bash
dev
```
Откроется интерактивный поиск `fzf` со списком всех доступных команд, их описанием и превью кода в правой панели. Начните вводить текст (например, `dock` или `sync`) и нажмите `Enter` для запуска.

Если вы хотите открыть меню только для определенной категории:
```bash
dev git
dev docker
dev laravel
```

### 2. Прямой запуск команд

Команды можно вызывать напрямую с передачей любых параметров:

```bash
# Формат 1: категория + команда
dev git sync
dev git sync feature-login
dev docker rebuild web
dev laravel migrate --seed
dev server health

# Формат 2: через дефис (как алиасы)
dev git-sync
dev docker-clean
dev laravel-reset

# Формат 3: через двоеточие
dev git:sync
dev docker:clean
```

### 3. Защита опасных операций (`@dangerous`)

Скрипты, изменяющие состояние данных или удаляющие файлы (например: `git reset-main`, `git clean`, `docker clean`, `laravel reset`, `server deploy`), помечены флагом `# @dangerous true`.

При их запуске лаунчер выведет предупреждение:

```text
┌─────────────────────────────────────────────────────────────┐
│  ⚠️   ВНИМАНИЕ: ОПАСНАЯ ОПЕРАЦИЯ!                            │
└─────────────────────────────────────────────────────────────┘
  Команда:     git reset-main (Git Reset Main)
  Описание:    Жестко сбросить ветку main к состоянию origin с удалением изменений
  Скрипт:      .../scripts/git/reset-main.sh

Эта операция может изменить или удалить локальные данные / ресурсы.
Вы действительно хотите продолжить? [y/N]: 
```

Если вы запускаете команду в CI/CD или автоматическом скрипте, подтверждение можно пропустить флагом `--force` или `-y`:

```bash
dev --force git reset-main
# или
dev -y docker clean
```

## 📦 Базовые команды "из коробки"

В наборе оставлены **только сложные и многосоставные операции**, цепочки команд которых неудобно или тяжело держать в голове:

Посмотреть актуальную таблицу всех команд в терминале:
```bash
dev list
```

| Команда | Опасность | Что делает под капотом |
| :--- | :---: | :--- |
| **`dev git purge-branches`** | **ДА** | Синхронизирует `git fetch -p`, находит и удаляет локальные ветки со статусом `[gone]` на сервере или смердженные в `main` |
| **`dev git find-large [N]`** | Нет | Сканирует всю историю Git (`rev-list + cat-file + sort`), находя топ-$N$ самых тяжелых файлов и блобов |
| **`dev git squash [count]`** | **ДА** | Объединяет последние N коммитов в один с сохранением изменений в staging (`git reset --soft HEAD~N`) |
| **`dev git undo`** | **ДА** | Интерактивный откат коммитов с выбором режима: soft (в staging), mixed (на диск), hard или поиск в `reflog` |
| **`dev docker nuke`** | **ДА** | Глубокая очистка Docker: остановка всех контейнеров, удаление orphaned-сетей, образов, томов и кэша BuildKit |
| **`dev docker db-dump [c]`** | Нет | Автоопределение СУБД (MySQL / Postgres / MariaDB) и выгрузка дампа из контейнера в сжатый `.sql.gz` на хосте |
| **`dev docker rebuild [s]`** | Нет | Чистая пересборка Compose: down с удалением orphan-контейнеров, build `--no-cache`, запуск и проверка статуса |
| **`dev laravel sail-setup`** | **ДА** | **Полный старт проекта через Sail с нуля**: ставит Composer в Docker без хост-PHP, `.env`, `sail up`, `key:generate`, `sail npm install/build`, миграции |
| **`dev laravel sail-install`**| Нет | Установка Composer-зависимостей через изолированный временный Docker-контейнер, если на хосте нет PHP |
| **`dev laravel sail-npm [...]`**| Нет | Выполнение команд NPM (`install`, `build`, `run dev`) внутри контейнера Laravel Sail |
| **`dev laravel reset`** | **ДА** | 8 шагов: down, composer dump-autoload, очистка кэшей и `bootstrap/cache`, `migrate:fresh --seed`, `storage:link`, права 775, up |
| **`dev server kill-port <p>`** | **ДА** | Поиск процесса, занявшего порт (`lsof`/`fuser`/`ss`), вывод PID, владельца, RAM и принудительное завершение |
| **`dev server disk-usage [p]`**| Нет | Поиск 15 самых тяжелых каталогов и файлов на диске (`du -ahx`) без зависания на системных псевдо-ФС |
| **`dev server ssl-check <dom>`**| Нет | Проверка SSL через OpenSSL: точные оставшиеся дни, дата истечения, эмитент и SAN без браузера |
| **`dev server permissions`** | **ДА** | Безопасные права веб-сервера: 755 директории, 644 файлы, 775 для `storage/cache` и защита `+x` на скриптах |
| **`dev server deploy [branch]`**| **ДА** | Пошаговый деплой: Git pull, Composer no-dev optimize, npm ci/build, миграции, кэш, перезапуск воркеров |
| **`dev update`** | Нет | Автообновление devtool через Git (`pull --ff-only`, вывод списка новых коммитов и обновление прав) |
| **`dev doctor`** | Нет | Проверка системных утилит (Bash 4+, Git, Docker, PHP, Composer, Node, NPM, fzf) |
| **`dev dev create <cat> <name>`**| Нет | Интерактивный генератор шаблона нового сценария с декларативными метаданными |

## 🏗 Архитектура хранилища

Каждый скрипт — это независимый bash-файл с декларативным блоком метаданных в начале:

```bash
#!/usr/bin/env bash
# @name Git Purge Dead Branches
# @description Очистить локальные ветки со статусом gone на сервере
# @usage dev git purge-branches [--force]
# @dangerous true

set -e
# Логика сложного сценария...
```

### Структура репозитория

```text
devtool-script/
├── bin/
│   └── dev                  # Главный исполняемый CLI-лаунчер
├── lib/
│   └── utils.sh             # Движок метаданных, цвета, подтверждения, поиск
├── scripts/                 # Базовое хранилище сложных сценариев
│   ├── git/                 # Сложные сценарии Git
│   │   ├── purge-branches.sh
│   │   ├── find-large.sh
│   │   ├── squash.sh
│   │   └── undo.sh
│   ├── docker/              # Комплексные сценарии Docker
│   │   ├── nuke.sh
│   │   ├── db-dump.sh
│   │   └── rebuild.sh
│   ├── laravel/             # Комплексные сценарии Laravel и Sail
│   │   ├── sail-setup.sh    # Полный запуск проекта с нуля (Composer в Docker + Sail + NPM)
│   │   ├── sail-install.sh  # Установка Composer через Docker без PHP на хосте
│   │   ├── sail-npm.sh      # Запуск NPM команд внутри контейнера Sail
│   │   └── reset.sh         # Полный 8-шаговый hard reset
│   ├── server/              # Серверные утилиты и DevOps
│   │   ├── kill-port.sh
│   │   ├── disk-usage.sh
│   │   ├── ssl-check.sh
│   │   ├── permissions.sh
│   │   └── deploy.sh
│   └── dev/                 # Служебные утилиты devtool
│       ├── update.sh
│       ├── doctor.sh
│       └── create.sh
├── install.sh               # Скрипт быстрой установки (curl & локально)
├── uninstall.sh             # Скрипт удаления
└── README.md
```

### Приоритет поиска скриптов (от высшего к низшему):
1. **Проектный уровень**: `./.dev/scripts/` или `./.dev/` в корне текущего рабочего каталога (позволяет переопределять или расширять команды под конкретный проект).
2. **Пользовательский уровень**: `~/.config/devtool/scripts/` или `~/.devtools/scripts/` (ваши персональные команды, не входящие в общий git-репозиторий).
3. **Базовый уровень**: `$DEV_ROOT_DIR/scripts/` (встроенные скрипты из этого репозитория).

## ✍️ Добавление своих команд

Вам **не нужно** редактировать исходный код лаунчера `bin/dev`. Достаточно просто добавить `.sh` файл!

### Способ 1: Использовать встроенный генератор

```bash
dev dev create mytools backup
```

Генератор автоматически создаст файл `scripts/mytools/backup.sh` с правильными заголовками:

```bash
#!/usr/bin/env bash
# @name Mytools Backup
# @description Описание того, что делает этот сценарий
# @usage dev mytools backup [параметры]
# @dangerous false

set -e

echo "==> Выполнение Mytools Backup..."
# Ваш bash код здесь
```

### Способ 2: Вручную создать файл

Создайте файл в папке категории, например `scripts/docker/logs.sh`:

```bash
#!/usr/bin/env bash
# @name Docker Service Logs
# @description Просмотр логов сервиса Docker Compose в реальном времени
# @usage dev docker logs [service_name]
# @dangerous false

set -e
docker compose logs -f --tail=100 "${1:-}"
```

Сделайте файл исполняемым:
```bash
chmod +x scripts/docker/logs.sh
```

Команда **сразу же** появится в `dev list`, меню `fzf` и будет доступна для вызова:
```bash
dev docker logs app
```

### Способ 3: Скрипты конкретного проекта

Если в вашем рабочем репозитории есть скрипты, нужные только в этом проекте, положите их в `.dev/scripts/` внутри проекта:

```text
my-project/
├── .dev/
│   └── scripts/
│       └── test/
│           └── run-e2e.sh
├── app/
└── ...
```
Когда вы находитесь в папке `my-project`, команда `dev test run-e2e` будет автоматически доступна!

## 🔄 Обновление и диагностика

### Проверка системы (`doctor`)
```bash
dev doctor
```
Проверяет наличие `bash 4+`, `git`, `docker`, `php`, `fzf` и показывает пути к каталогам скриптов.

### Обновление лаунчера
Обновить DevTool можно любым из двух простых способов:

**Способ 1 (из любого места в терминале):**
```bash
dev update
```
Команда выполнит `git pull --ff-only`, покажет список новых коммитов и автоматически обновит права на все новые скрипты.

**Способ 2 (через curl):**
```bash
curl -fsSL https://raw.githubusercontent.com/GregoryBiter/devtool-script/main/install.sh | bash
```
Установщик обнаружит существующую копию в `~/.devtools`, подтянет свежие изменения через Git и актуализирует символические ссылки.

## ⚙️ Альтернативная ручная установка

Если вы предпочитаете склонировать репозиторий вручную в произвольную папку:

```bash
git clone https://github.com/GregoryBiter/devtool-script.git ~/dev/devtool-script
cd ~/dev/devtool-script
./install.sh
```

*(Для глобальной установки в `/usr/local/bin`: `./install.sh --global`)*

### Рекомендуется: установить `fzf` (для интерактивного поиска с превью)

```bash
# Ubuntu / Debian
sudo apt install fzf

# macOS
brew install fzf

# Fedora / RedHat / CentOS
sudo dnf install fzf
```

## 🗑 Удаление

Если вы хотите удалить символические ссылки `dev`:
```bash
./uninstall.sh
```
Для полного удаления вместе с каталогом `~/.devtools`:
```bash
./uninstall.sh --purge
```
